# 文档写作规范（OpenSpec 先行）

## 核心规则

**不允许跳过 OpenSpec 直接写文档正文。** 文档也是交付物，结构错了返工成本高。

写文档的流程固定为：

1. **创建 OpenSpec change**（`openspec new change`），change 名体现文档主题（如 `research-core-docs`）。
2. **在 `design.md` 里写明白**：
   - 文档的目标读者（自己回顾 / 团队协作 / 导师或临床合作者）
   - 完整的章节结构（到二级标题）
   - 每一节要表达什么、论证什么、下什么结论
   - 文档之间的引用关系（如实现路径引用算法框架的概念）
3. **在 `tasks.md` 里列出写作任务**：按章节拆分，含资料调研类任务（医学背景、文献）和评审类任务。
4. **用户审核通过 design/tasks 后**，才能开始写文档正文。

## 例外

- README 级别的简短说明（几十行内）可以直接写。
- 修改已有文档的错别字、坏链接可以直接改。
- 其余一律走上述流程。

## 写作要求

- 文档放 `docs/` 对应子目录（科研文档 `docs/research/`）。
- 涉及医学、领域背景知识的内容，必须在 design 阶段列出需要调研的知识点，不得凭空编造。
- 文档中引用代码路径、数据路径时，必须与仓库实际结构一致。
- 中文文档使用一致的术语表；首次出现的缩写给出全称。
